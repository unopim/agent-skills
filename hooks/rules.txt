# ---------------------------------------------------------------------------
# grep-gate rule table. One rule per line, TILDE-delimited:
#
#     id~path-regex~content-regex~message
#
# The delimiter is ~ rather than | because nearly every regex below needs |
# for alternation. No field may contain a ~. Lines starting with # are
# comments; blank lines are ignored.
#
# Both regexes are PCRE (grep -P), matched unanchored: the path regex against
# the edited file path, the content regex against ONLY the lines this edit
# added. Exclusions belong in the path regex, written as a leading
# ^(?!.*<excluded>) lookahead so they read next to what they exempt.
#
# The message is fed to the model when the rule fires, so it must state the
# FIX, not the sin. Keep one blank-line-separated group per concern; the
# groups are the tuning unit.
#
# NEW_CSS_FILE is a path rule, not a content rule, and lives in grep-gate.sh,
# alongside the vendored/generated path skips every rule inherits.
#
# CALIBRATION. Every rule below is tuned against a real baseline: the files
# touched by the last 40 commits of the unopim-variants working tree: 1261
# files, 1007 after grep-gate.sh drops the vendored and generated paths, each
# treated as if wholly added, which is how the gate sees a new file. The
# target is zero hits on idiomatic core code, because a rule that fires on
# code the team writes on purpose teaches the model to route around the gate.
# Hit counts quoted in the comments are against that baseline. Re-run the
# calibration before widening any regex.
#
# Two shared exclusions recur and mean the same thing everywhere:
#   /[Tt]ests?/, .spec., .test.  Test code is not product code: fixture
#       colours, selector strings, step comments and Arrange/Act/Assert
#       banners are all correct there.
#   Resources/views/(public|errors)/  Standalone <!doctype html> pages served
#       outside the admin bundle (product passport, publication error pages).
#       Like emails, they have no Tailwind and no CSS-variable theme, so hex,
#       rgba() and <style> are the only thing that works.
# ---------------------------------------------------------------------------

# --- Design system -----------------------------------------------------
# Source of truth: packages/Webkul/Admin/tailwind.config.js and
# src/Resources/assets/css/app.css. tailwind.config.js declares the tokens and
# the legacy families, so it is exempt. Resources/views/emails is exempt from
# this whole group and the next: mail clients do not run Tailwind or CSS
# variables, so inline styles, hex literals and table layout are correct there.
#
# Installer/src/Resources/views is exempt from this whole group for the same
# structural reason. That page renders before the application exists: it pulls
# in zero x-admin components, carries zero `dark:` classes, and has no config
# table to read a theme from, so there is no token layer for it to use.
#
# INLINE_STYLE: the (?<![:\w-]) lookbehind is what separates a static
# style="width: 240px" (fixable) from Vue's :style="gridTemplate(columns)" and
# :style="{ background: record.swatch_value }" (a runtime-computed binding
# that no utility class can express). 37 -> 16 hits, every one of them a
# static declaration a utility class can carry.
INLINE_STYLE~^(?!.*(Resources/views/(emails|public|errors)/|Installer/src/Resources/views/|/[Tt]ests?/|\.spec\.|\.test\.)).*\.(blade\.php|vue)$~(?<![:\w-])style="~Inline styles bypass the design tokens and dark mode. Express it as Tailwind utility classes on the element.

# STYLE_BLOCK now exempts Resources/views/components/ on the same principle as
# the three rules below it: a component is where the markup and the CSS it
# cannot express are allowed to live. All 8 baseline hits were that -- the
# root layout injecting the operator's own
# general.content.custom_scripts.custom_css, a [v-cloak] FOUC guard for the
# <v-promo-bar> custom element, a ::-webkit-search-cancel-button reset. None
# is expressible as a utility class. What is left is the target: a feature
# page shipping its own CSS. 8 -> 0 hits.
STYLE_BLOCK~^(?!.*(Resources/views/(emails|public|errors)/|Resources/views/components/|Installer/src/Resources/views/|/[Tt]ests?/)).*\.(blade\.php|vue)$~<style[\s>]~A style block bypasses the design system. Express it as Tailwind utility classes, or add the token to app.css.

# HEX_COLOR: (?<!&) and the (?![0-9]{3,4}\b) veto drop the two things that are
# not colours and made up most of the noise -- HTML numeric entities (&#9650;
# for a caret glyph) and GitHub issue references (Issue #243, "(#755)"). Cost:
# a pure-digit short hex such as #000 is no longer caught; #000000 still is.
# 49 -> 10 hits. components/tinymce is exempt as well: its hex lives in the
# content_style string TinyMCE injects into its own editor iframe, a
# document the admin stylesheet never reaches. Of the 10 that remain, 8 are
# an SVG icon fill="#27272A" -- real, and fixable with fill="currentColor".
# KNOWN RESIDUAL, 1 line: configuration/field-type.blade.php seeds a colour
# PICKER with :value="value != '' ? value : '#ffffff'". That hex is data the
# user is about to overwrite, not styling, and it is indistinguishable on one
# line from fill="#ffffff". Left in deliberately rather than papered over.
HEX_COLOR~^(?!.*(tailwind\.config\.js|Resources/views/(emails|public|errors)/|Resources/views/components/tinymce/|Installer/src/Resources/views/|/[Tt]ests?/|\.spec\.|\.test\.)).*\.(blade\.php|vue|js)$~(?<!&)#(?![0-9]{3,4}\b)([0-9a-fA-F]{8}|[0-9a-fA-F]{6}|[0-9a-fA-F]{3,4})\b~A hex colour cannot follow the .dark CSS variable swap, so dark mode breaks visibly. Use a semantic class: primary, primary-hover, success, warning, danger or info.

# RGB_COLOR: (?<![_\[]) exempts Tailwind arbitrary values, where the rgba()
# sits inside the class itself -- shadow-[0px_8px_24px_0px_rgba(0,0,0,0.05)].
# That IS a utility class, so demanding one back was incoherent. 17 -> 0 hits.
RGB_COLOR~^(?!.*(tailwind\.config\.js|Resources/views/(emails|public|errors)/|Installer/src/Resources/views/|/[Tt]ests?/|\.spec\.|\.test\.)).*\.(blade\.php|vue|js)$~(?<![_\[])rgba?\(\s*(?!var\()~A colour literal cannot follow the .dark variable swap. # CSS_COLOR_LITERAL is what keeps an ALREADY-TRACKED stylesheet honest.

# --- Components --------------------------------------------------------
# 40+ component directories already exist under
# packages/Webkul/Admin/src/Resources/views/components. The components
# themselves are exempt: they are where the raw markup is allowed to live.
#
# RAW_FORM_CONTROL previously exempted only components/form/, which
# contradicted the paragraph above and made every other component directory --
# media, associations, tinymce, products, categories -- a violation for
# containing the markup it exists to encapsulate. It now exempts
# Resources/views/components/ like its two neighbours do. The Installer views
# are exempt too: that page loads zero x-admin components (it renders before
# the app is installed), so there is nothing to wrap the field in. Hidden
# inputs are exempt because a control-group has no way to express one -- no
# label, no error slot, nothing to render. 167 -> 64 hits.
#
# KNOWN RESIDUAL, the one this table cannot close: 28 of those 64 are a hidden
# input written across several lines, where `type="hidden"` sits on the line
# AFTER `<input` and a line-scoped grep cannot see it. The exemption cannot be
# widened to a bare `<input` line without losing the rule's best catch -- a
# hand-rolled `<input type="text">` carrying a copy-pasted class list inside a
# control-group, which is written exactly the same way. So the message names
# the exemption instead, and the model resolves it in one read. Closing this

# before matching; until then, treat a hidden-input hit as a no-op.

# RAW_LISTING covers the listing RAW_TABLE cannot see. RAW_TABLE keys on the

# --- Comments -----------------------------------------------------------
# The bar is ABSOLUTE, by the repository owner's decision (2026-07-31):
# no inline comments in code. Not a narration, not a one-line "why", not a
# banner, not commented-out code, not a Blade comment. A rationale worth
# keeping goes in the class or method PHPDoc (/** ... */), which these rules
# never touch, or in the commit message. Code carries its meaning in names.
#
# The ratchet is what makes an absolute bar liveable: these rules judge only
# the lines an edit ADDS. The comments already in the codebase stay exactly
# where they are and block nothing; what they cannot do is grow. Measured on
# the added lines of the last five commits, the rule fires 3 times.
#
# Allowed and never matched: /** PHPDoc */ blocks and their " * " body lines,
# PHP 8 attributes (#[Fillable]), URLs inside strings, and anything under a
# tests directory or a .spec./.test. file, where a comment marks intent for a
# reader who cannot see the assertion's purpose from its name. A rationale in
# a Vue computed or a <script> block therefore goes in a /** */ block too —
# there is no method PHPDoc to move it to, and the rule already permits one.
#
# Config files are handled by CONFIG_COMMENT below rather than here.
INLINE_COMMENT~^(?!.*(/[Tt]ests?/|\.spec\.|\.test\.|/[Cc]onfig/[^/]*\.php$)).*\.(php|js|vue)$~(^|\s)//(?!.*(?:https?:|s3:|ftp:|file:))|^\s*/\*(?!\*)|\S\s+/\*(?!\*)|^\s*#(?!\[|!)~Delete it. UnoPim code carries no inline comments: rename the variable or extract a method until the line explains itself, and put a rationale worth keeping in the method PHPDoc.

# CONFIG_COMMENT is INLINE_COMMENT minus the block-comment arm, because a
# config array is the one place the "move it to the PHPDoc" escape hatch does
# not exist: there is no method to attach one to, and the value being explained
# is a literal. Laravel writes the rationale as a /* |--- */ banner and so does
# UnoPim — 14 of the 53 package configs on master, `packages/Webkul/Admin/src/Config/acl.php`
# and `packages/Webkul/Admin/src/Config/media.php` among them. Blocking that
# shape would be blocking the house style. Narration still has no place here,
# so // and # stay blocked.
CONFIG_COMMENT~^(?!.*(/[Tt]ests?/)).*/[Cc]onfig/[^/]*\.php$~(^|\s)//(?!.*(?:https?:|s3:|ftp:|file:))|^\s*#(?!\[|!)~Delete it. A config value explains itself through its key and a /* |--- */ banner block, the way Laravel and the core package configs do. Line comments narrate; the banner documents.
BLADE_COMMENT~^(?!.*(/[Tt]ests?/|\.spec\.|\.test\.)).*\.blade\.php$~\{\{--~Delete it. Blade markup carries no comments: name the section with a component or a variable, and put anything a maintainer must know in the PHPDoc of the code that feeds this view.

# RAW_SQL_INTERPOLATION replaces DB_RAW_INTERPOLATION, which recognised the
# token DB::raw( and nothing else. whereRaw, selectRaw, orderByRaw and
# havingRaw carrying a directly interpolated request value were all invisible,
# and so was the injectable fragment this codebase's search boxes actually
# produce: LIKE '%$search%', which the old [^"']* class could not reach across
# the inner quote. The value-position requirement is KEPT verbatim -- after =,
# < , >, LIKE or IN ( -- because it is what holds the false positives at zero.
#
# Measured 0 hits. It was validated in both directions rather than by count
# alone: 7 of 7 on a must-catch corpus (LIKE with and without braces, id = $id,
# DB::raw nested inside whereRaw, havingRaw with COUNT), and 0 of 10 on a
# must-NOT corpus built from the shapes the old rule was narrowed to avoid --
# whereRaw("COALESCE($searchPath, '') = ''") and whereRaw("$column IS NULL")
# from the Product database filters (10 real lines in core),
# DB::raw($this->axisCodesSubQuery('level_1').' as level_1_axes'),
# DB::raw("{$jsonExpr} as attr_value"), the rawQueryGrammar and $prefix
# fragments, and the bound whereRaw('col = ?', [$value]).
#
# KNOWN RESIDUAL, deliberate: orderByRaw("$column $direction") is NOT caught.
# It is character-for-character the shape of whereRaw("$column IS NULL"), which
# is correct code in five core filter classes, so no line-level regex can
# separate a whitelisted sort column from a request-supplied one. DataGrid sort
# handlers are a review dimension (unopim-code-review section 6), not an exit
# code. selectRaw("CONCAT(name, '$search')") and DB::raw(sprintf(...)) are out
# for the same reason the old rule documented: laundered through a helper.
RAW_SQL_INTERPOLATION~^(?!.*(/[Tt]ests?/|\.spec\.|\.test\.)).*\.php$~(?:whereRaw|selectRaw|orderByRaw|havingRaw|DB::raw)\(\s*["'][^"']*(?:=|<|>|\bLIKE\b|\bIN\b\s*\()\s*['"%]*\s*[.{]?\s*\$~Bind the value instead of interpolating it into the SQL: whereRaw('col = ?', [$value]), or a query builder method. A SQL fragment built from an internal column path, from $prefix or from DB::rawQueryGrammar() is not this rule.

# --- Scale -------------------------------------------------------------
# 0 baseline hits: the static-facade veto list already covers every ::all()
# the core actually calls, and ->all() on a collection can never match because
# the regex demands a ClassName:: prefix.
#
# The veto list now carries the SMALL ENTITIES too. scale.md:31 permits all()
# for attributes, categories, families and the config-shaped tables, so
# Channel::all() and Locale::all() -- three to twenty rows, the idiomatic
# lookup -- were code the rule blocked and the doc blessed. Still 0 hits; the
# widening only removes a latent false positive that fires the first time an
# agent writes the correct thing.
MODEL_ALL~^(?!.*(/[Tt]ests?/|\.spec\.|\.test\.)).*\.php$~\b(?!(Config|Cache|Session|Request|Cookie|Auth|Arr|Str|Route|Storage|View|Lang|App|Schema|Channel|Locale|Currency|Theme|Role|AttributeFamily|AttributeGroup)::)[A-Z][A-Za-z0-9_]*::all\(\)~Unbounded reads do not scale to a catalogue of millions. Use paginate(), chunkById(), lazyById(), or a repository method that limits the set.

# REPO_ALL is the largest hole MODEL_ALL left. Its regex demands a ClassName::
# prefix, so $this->productRepository->all() -- the same catalogue-wide read,
# written the way AGENTS.md and every skill file tell an agent to write it --
# walked straight through, and an agent blocked once by MODEL_ALL learns that
# spelling on the retry.
#
# The small-entity names carry the same veto as MODEL_ALL, and here it is
# load-bearing rather than latent: unvetoed the rule fired 24 times over 16
# files and almost every hit was $this->localeRepository->all(),
# $this->channelRepository->all() or $this->currencyRepository->all() in Core
# and the product validators -- exactly what scale.md:31 permits. 2 hits
# remain, one of them the genuine target ($productRepository->all() in
# AiAgent/src/Examples).
#
# $this->model->all() is deliberately NOT part of this rule. It measured 3
# hits, all 3 inside the attribute, family and category repositories, where
# the entity is small and the call is correct -- 100% false positive. At a
# $this->model call site the entity name is invisible; at a repository call
# site it is in the variable, which is why the judgment lives here.
REPO_ALL~^(?!.*(/[Tt]ests?/|\.spec\.|\.test\.)).*\.php$~\$(?:this->)?(?!(?i:locale|currency|channel|theme|role|attribute|attributeFamily|attributeGroup|attributeOption|family|group)[Rr]epository\b)[A-Za-z0-9_]*[Rr]epositor(?:y|ies)->all\(\)|Repository::class\s*\)->all\(\)~A repository all() is the same unbounded read as Model::all(). Use paginate(), chunkById(), lazyById(), or a repository method that limits the set.

# SELECT_STAR: 0 hits. Core never writes it, and it is the one purely
# mechanical piece of performance.md:73 a single line can carry.
SELECT_STAR~^(?!.*(/[Tt]ests?/|\.spec\.|\.test\.)).*\.php$~->select\(\s*['"]\*['"]\s*\)~select() only the columns the code reads. A select('*') on a catalogue table pulls every column into memory for rows that never use them.

# NOT ENFORCED HERE, on purpose. These four were measured and rejected; the
# numbers are recorded so the next reader does not re-propose them.
#   N+1 in a loop, and a missing eager load. grep-gate matches a PCRE against
#       added lines with no block or scope awareness, so it cannot know a
#       ->count() sits inside a foreach. Genuinely not a line property.
#   An unbounded fluent ->get() on a catalogue table. Reaching it needs the
#       added lines re-joined into statements; the proposed rule measured 70
#       hits over 56 files that way, and they were ProductProxy::observe(),
#       Product::class and ProductProxy::modelClass() -- the joined buffer
#       glues docblocks and class bodies into one "statement", so the shape
#       stops meaning anything.
#   Bulk work inline in a controller. The proposed proxy flagged
#       ->chunkById( and ->lazyById( inside Http/Controllers, which are the
#       RECOMMENDED streaming primitives: its only hit in core was a correct
#       $product->variants()->lazyById(). A rule that flags the fix teaches
#       the wrong lesson.
#   A singleton holding request state. $this->app->singleton( measures 29 hits
#       across Core, Product, Attribute and Webhook, and performance.md:63
#       says singleton is CORRECT for stateless registries.
# All four are review dimensions in skills/unopim-code-review, sections 5
# and 6, and named as unhooked in performance.md and scale.md.

# --- Localization ------------------------------------------------------
HARDCODED_ATTR~^(?!.*(/[Tt]ests?/|\.spec\.|\.test\.)).*\.(blade\.php|vue)$~\s(placeholder|title|label|alt)="[A-Z]~Wrap it in trans('package::file.key'), add the key to en_US, and propagate the translated value to all 33 locales.
HARDCODED_OPTION~^(?!.*(/[Tt]ests?/|\.spec\.|\.test\.)).*\.blade\.php$~<option[^>]*>\s*[A-Z]~Build the options from trans() values in the controller, or pass them as the select component's options payload.

# BLADE_TEXT_NODE: the old ^\s*[A-Z][a-z]+\s[a-z]+ branch matched ANY indented
# English sentence, so all 12 baseline hits were prose inside {{-- --}} header
# comments -- grep cannot see that it is inside a block comment. The bare-line
# branch now has to be the WHOLE line and at most five words, which is the
# shape of a label and not the shape of a wrapped comment sentence. Cost: a
# hardcoded full sentence broken across lines inside a <p> is no longer
# caught. 12 false positives -> 0, and it now finds 2 real ones (the
# accordion's "Default Header" / "Default Content" slot placeholders). 12 -> 2.
BLADE_TEXT_NODE~^(?!.*(/[Tt]ests?/|\.spec\.|\.test\.)).*\.blade\.php$~(>\s*[A-Z][a-z]+\s+[a-z]+\b|^\s*[A-Z][a-z]+(\s+[A-Za-z']+){1,4}\s*$)~Move the sentence into a translation key and echo trans('package::file.key'). Bare text in markup cannot be localized.

# --- CRUD page patterns ------------------------------------------------
# The trailing ['"] anchors "create" to the end of the route path, so
# Route::get('exports/{id}/create-mapping') is not a create page.
GET_CREATE_ROUTE~^(?!.*(/[Tt]ests?/|\.spec\.|\.test\.)).*Routes/.*\.php$~Route::get\(\s*['"][^'"]*create['"]~Create is a code and label modal on the index page, and store() redirects to the edit page. Drop the GET create route and its page.
